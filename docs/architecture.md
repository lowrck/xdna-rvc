# Architecture

## Pipeline

```
 capture callback ──► input SPSC ring ──► inference worker ──► output SPSC ring ──► playback callback
 (audio thread)        (lock-free)        StreamProcessor        (lock-free)        (audio thread)

 StreamProcessor::process(one hop):
   gain/gate → resample to 16 kHz → slide window (T frames of 10 ms)
   ├─ content encoder (HuBERT/ContentVec, ONNX)  ── whole window ──► features (50 Hz, +1 frame)
   └─ RMVPE (helper thread, concurrently)         ── newest 310 ms ──► F0 cache (shift by hop)
   index blend (IVF-Flat, CPU) on frames ≥ E/2 → ×2 repeat to 100 Hz → protect mix
   generator (fixed shapes; decodes frames [E, E+H+Cb+S)) → RMS mix → SOLA crossfade → gain
   → resample to device rate → FIFO → one hop out
```

Window geometry (10 ms frames): `T = E + C + S + H + L`, decode `R = H + min(C,4) + S` frames
starting at `E`. E = context, C = crossfade, S = 1 SOLA search frame, H = hop, L = lookahead.
With L = 0 this is upstream RVC's realtime structure. See `src/rvc/stream_config.h` and the
mirrored `tools/xdna_rvc_tools/stream_config.py` (tested against the same table).

**One code path:** realtime audio, offline WAV conversion (`convert_offline`) and benchmarks all
drive the same `StreamProcessor`, so offline results reproduce realtime behaviour.

## Threads and realtime safety

| Thread | Does | Must not |
|---|---|---|
| Audio capture/playback (miniaudio) | copy to/from SPSC rings, atomics, `atomic::notify_one`, fade on underrun | allocate, lock, log, I/O, inference, wait on the GUI |
| Inference worker | wait for a hop, run `StreamProcessor`, push output, drift control, stats | — (runs at MMCSS "Pro Audio" / SCHED_FIFO where permitted) |
| RMVPE helper | pitch for the current hop, concurrently with the content encoder | — |
| ORT global pool | operator kernels for all stages (shared, raised priority in realtime) | — |
| GUI | edit parameters (atomics), read engine snapshots (mutex, worker uses `try_lock`) | DSP |

Failure handling: underrun → short fade to silence (or dry bypass when rates match); input
backlog > 3 hops → drop oldest input (bounded latency); inference exception → silent hop +
counter; separate device clocks → ±1 sample per hop stretch toward a learned queue level;
latency added by underruns → trimmed during silent blocks. All counters are shown in the GUI.

## Backends

`IInferenceBackend` (`src/inference/inference_backend.h`) configures ORT session options for one
execution provider: `CpuBackend`, `DirectMLBackend` (entry point resolved from `onnxruntime.dll`
at runtime, so no d3d12/DirectML headers are needed), `Xdna2Backend` (VitisAI EP).
`BackendKind::CUDA/ROCm` exist in the configuration format but have no implementation.

`ModelSession::open` tries the requested backend (Automatic: XDNA 2 → DirectML → CPU). Skipping an
uninstalled backend in Automatic mode is a *selection*; a failure of an available backend or a
not-honoured explicit request is a *fallback* — logged as a warning, recorded in the
`SessionReport`, shown in the GUI. Nothing falls back silently.

Each stage owns its session, so placements can differ (e.g. content encoder on XDNA 2, RMVPE on
CPU, generator on DirectML).

### Execution evidence

"Provider registered" is not treated as "runs on the NPU". Each session is created with ORT
profiling for one probe run; the profile records the execution provider of every node, from
which node counts and time shares per provider are computed. For XDNA 2 the VitisAI EP operator
assignment report (`XLNX_ONNX_EP_REPORT_FILE`) is parsed as well. `npu_evidence()` requires
nodes attributed to the NPU by one of these.

## Fixed shapes

The NPU compiler needs static shapes, and realtime inference should not use dynamic sizes:

* Generators are exported per stream geometry (`generator_T{T}_s{S}_r{R}.onnx`).
* The content encoder and RMVPE are exported with a dynamic length and pinned at session creation
  (ORT free-dimension overrides). For XDNA 2 a static copy is written (dims pinned, graph not
  re-optimised: re-optimising pinned graphs trips an ORT 1.30 load bug) and precompiled by
  `tools/compile_xdna.py`.

## Model formats and conversion

`tools/` converts upstream checkpoints and validates every artefact: content encoder vs
Transformers `HubertModel`; synthesizer export model vs upstream `infer()` with identical injected
noise (bit-identical in most geometries); ONNX vs PyTorch (≤ 1e-3 abs, ≤ 1e-4 rel. RMS);
native IVF search vs FAISS; C++ stages vs Python references. Randomness (flow prior, NSF noise)
is an explicit model input, generated by the runtime.

## Deviations from the original brief (and why)

| Brief | Decision | Reason |
|---|---|---|
| FAISS for .index | Export FAISS IVF lists to `.npy`, native IVF-Flat search | Avoids FAISS/BLAS in the native build; verified identical to FAISS |
| Vitis AI "compile at runtime" | Precompile BF16 with `compile_xdna.py` | Ryzen AI 1.8 deployment EP cannot compile BF16 on the fly |
| ASIO | Not implemented | Needs the Steinberg SDK; WASAPI exclusive covers low latency |
| Fixed processing windows 80–160 ms, hops 10–40 ms | Hop/crossfade/context/lookahead geometry; 10 ms hops impractical | Per-hop cost has a large fixed part (HuBERT over the window); measured in docs/latency.md |
| Window = context | Added explicit lookahead | Measured: small hops without lookahead lose intelligibility |
| INT8 | Not used | Precision policy: BF16 first, FP32 reference (docs/implementation_plan.md) |

```

src/dsp         resampler, FFT, SOLA, RMS mixer
src/rvc         stream config, model.json, content encoder, RMVPE, index, generator,
                StreamProcessor, offline conversion
```
